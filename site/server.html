Сервер

VPS не входит в поставку. Нужен свой сервер с публичным адресом и доменом: раннер GitHub и GitLab не видит localhost, поэтому стенд на рабочей машине для CI недоступен.

Что нужно от вас

Сервер у выбранного провайдера, домен с A-записью на адрес сервера и сертификат для HTTPS. Всё остальное ставится командами ниже. Развёртывание рассчитано на Docker Compose на одной машине: кластер, балансировка и внешняя PostgreSQL сюда не входят.

  1. Возьмите сервер и домен

    Нужен Ubuntu 24.04 LTS, 2 ГБ ОЗУ и больше. A-запись домена должна указывать на публичный адрес сервера до выпуска сертификата.

  2. Создайте пользователя без root

    adduser deploy
usermod -aG sudo deploy

    С локальной машины:

    ssh-copy-id deploy@<домен>

    Дальше все команды выполняются в сеансе этого пользователя. Проверка: sudo -v спрашивает пароль и не выдаёт ошибку.

  3. Закройте порты файрволом

    sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status

    Порты 8000 и 5432 наружу не открывайте: обратный прокси обращается к API локально, а PostgreSQL нужен только контейнерам.

  4. Поставьте Docker

    Официальная инструкция: Docker для Ubuntu. Скрипт установки из той же документации: 

    curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER

    Выйдите из сеанса и войдите снова, чтобы применилась группа docker, затем проверьте: 

    docker version
docker compose version

    Ожидаемо: заполнены разделы Client и Server, плагин Compose печатает версию.

  5. Клонируйте репозиторий

    git clone https://github.com/arslan-ahmetjanov/patches-please.git
cd patches-please

  6. Настройте .env

    Смените пароль базы и включите режим для HTTPS:

    cp .env.example .env

    В файле задайте режим и пароль базы. Пароль в двух строках должен совпадать: 

    APP_ENV=production
POSTGRES_PASSWORD=<надёжный пароль>
DATABASE_URL=postgresql+psycopg://patches_please:<надёжный пароль>@postgres:5432/patches_please

    Пароль должен совпадать в POSTGRES_PASSWORD и в DATABASE_URL. API_PORT оставьте равным 8000. Compose публикует порт на всех интерфейсах, поэтому наружу его закрывает файрвол из шага 3, а обратный прокси обращается к API по 127.0.0.1.

  7. Соберите и запустите стек

    docker compose up -d --build

    Ожидаемо: четыре контейнера в состоянии Up, у всех пометка (healthy). Первая сборка скачивает базовый образ, сканеры и базу Trivy.

  8. Поставьте uv и создайте аккаунт

    curl -LsSf https://astral.sh/uv/install.sh | sh

    В новом терминале:

    uv sync
uv run alembic upgrade head

    Затем сев:

    export DEMO_PASSWORD='<пароль не короче 8 символов>'
export DEMO_REPO_URL='https://github.com/arslan-ahmetjanov/patches-please-demo.git'
uv run python scripts/seed_demo.py

    Токен из вывода сохраните: он показывается один раз. Если стенд нужен без демо, укажите в DEMO_REPO_URL адрес своего публичного репозитория.

  9. Поставьте nginx и certbot

    sudo apt-get update
sudo apt-get install -y nginx certbot python3-certbot-nginx

    Конфигурация сайта в /etc/nginx/sites-available/patches-please: 

    server {
    listen 80;
    server_name patches.example.ru;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

    Замените patches.example.ru своим доменом, включите сайт и проверьте конфигурацию: 

    sudo ln -s /etc/nginx/sites-available/patches-please /etc/nginx/sites-enabled/patches-please
sudo nginx -t
sudo systemctl reload nginx

    Выпустите сертификат: certbot сам допишет блок для 443 и настроит редирект.

    sudo certbot --nginx -d <домен>

  10. Проверьте стенд снаружи

    curl https://<домен>/health

    Ожидаемо: HTTP 200 и тело {"status":"ok"}. Вход: https://<домен>/login.

    Без HTTPS вход не работает

    APP_ENV со значением, отличным от local, включает Secure у cookie сессии и CSRF. По HTTP браузер такие cookie не отправит, и вход не сохранится. Сначала сертификат, потом проверка входа.

  11. Настройте резервные копии

    Пользователь и база в командах совпадают с POSTGRES_USER и POSTGRES_DB: 

    docker compose exec -T postgres pg_dump -U patches_please patches_please > backup.sql

    Поставьте её в cron и храните файлы вне сервера. Том reportsdata с отчётами копируется отдельно: внутри контейнера это каталог /app/reports. Проверку восстановления делайте на отдельном стенде: 

    docker compose exec -T postgres psql -U patches_please patches_please < backup.sql

  12. Обновляйте стенд

    git pull
docker compose up -d --build
uv run alembic upgrade head

    Пересборка обязательна и тогда, когда обновилась база уязвимостей Trivy: она зашита в образ worker и между пересборками не меняется.

Что учесть на сервере

  • Клон идёт по сети. Сканеры работают офлайн, но worker клонирует репозиторий проекта с GitHub или GitLab. Серверу нужен исходящий доступ к провайдеру, иначе прогон завершится статусом error.
  • Приватный репозиторий не клонируется. Учётных данных для клонирования у worker нет: указывайте публичный HTTPS-адрес в repo_url.
  • Отдельного домена для API не нужно. Интерфейс и REST API живут на одном сервисе, поэтому одного адреса хватает. В PATCHES_PLEASE_URL для CI укажите этот же адрес без /api/v1.
  • Миграции отдельным шагом. API не применяет их при старте: после каждого git pull нужен uv run alembic upgrade head.

Дальше подключите сервис к пайплайну: «CI». Если что-то не поднимается, начните с раздела «Неполадки».
