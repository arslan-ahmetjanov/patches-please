Установка

Стенд поднимается на одной машине четырьмя сервисами Docker Compose. Ниже порядок из runbook: предусловия, восемь шагов с командами, проверка и переход к настройке. После каждой команды указано, что должно появиться в выводе.

Что получится

Команда docker compose up -d --build поднимает четыре сервиса.

Сервисы локального стенда
Сервис Роль Порт
postgres Схема БД и история прогонов 5432
redis Очередь RQ не публикуется
api REST API, страницы интерфейса, /health 8000
worker Очередь, клон репозитория, три сканера, отчёты не публикуется

После развёртывания доступны три адреса:

  • http://localhost:8000/health отдаёт healthcheck сервиса;
  • http://localhost:8000/login открывает вход в интерфейс;
  • http://localhost:8000/docs показывает интерактивную схему API.

На развёртывание с чистой машины отводится 30 минут. Замер по этой инструкции: 5 мин 51 с (351.3 с). Основное время занимает первая сборка образов, повторная проходит быстрее за счёт кеша слоёв.

Что понадобится

Предусловия установки
Что Требование Как проверить
ОС Windows 10/11 x64 с WSL2, macOS 13+, Linux x64/arm64 не требуется
Docker Docker Desktop на Windows и macOS, на Linux Docker Engine с плагином Compose docker version, docker compose version
uv 0.13 или новее, проверено на 0.13.9 uv --version
git любая актуальная версия git --version
Порты 8000 и 5432 свободны netstat -ano | findstr :8000 (Windows)
Место на диске С запасом под два образа, тома PostgreSQL и Redis и каталог отчётов не требуется
Проверка Docker

docker version считается успешным, только если в выводе есть и Client:, и Server:. Один Client: без Server: означает, что движок не запущен, и идти дальше нельзя.

Шаги

  1. Получите репозиторий

    git clone https://github.com/arslan-ahmetjanov/patches-please.git
cd patches-please

    Ожидаемо: код возврата 0, в каталоге появились docker-compose.yml, Dockerfile, Dockerfile.worker и pyproject.toml.

  2. Установите uv

    Windows, PowerShell:

    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

    macOS и Linux:

    curl -LsSf https://astral.sh/uv/install.sh | sh

    Откройте новый терминал, проверьте версию и поставьте зависимости проекта:

    uv --version
uv sync

    Ожидаемо: строка вида uv 0.13.9 (версия может быть новее) и код возврата 0. uv скачает Python 3.12 по .python-version и создаст .venv. Шаг нужен для команд с хоста: миграций, сева, CLI и тестов; сам стек Docker работает и без него.

  3. Запустите Docker Desktop

    Дождитесь состояния «Engine running», затем проверьте движок: 

    docker version
docker compose version

    Ожидаемо: в docker version заполнены разделы Client и Server; docker compose version печатает версию плагина, код возврата 0.

    Если вывод заканчивается ошибкой failed to connect to the docker API ... dockerDesktopLinuxEngine, движок не поднят. На Windows служба запускается только с правами администратора: 

    sc start com.docker.service

    Ошибка 5 («Отказано в доступе») означает, что прав не хватило.

  4. Скопируйте пример окружения

    cp .env.example .env

    PowerShell:

    Copy-Item .env.example .env

    Ожидаемо: в каталоге появился файл .env, код возврата 0. Файл не коммитится и в образ не копируется. Значения по умолчанию годятся только для локального стенда, переменные разобраны на странице «Настройка».

    Порт 8000 на Windows

    Windows резервирует диапазон портов с 7979 по 8078. Если 8000 попал в него, запуск завершается ошибкой bind: address already in use, хотя порт свободен. Посмотрите занятые диапазоны: 

    netsh interface ipv4 show excludedportrange protocol=tcp

    Обойдите ограничение через .env: задайте API_PORT=8081. Дальше вместо 8000 в адресах будет 8081, порядок шагов не меняется.

  5. Соберите и запустите стек

    docker compose up -d --build

    Ожидаемо: код возврата 0, в конце вывода строки Started или Running для четырёх контейнеров. Первая сборка скачивает базовый образ, Semgrep, Gitleaks, Trivy и базу Trivy; сеть нужна только на этом шаге.

  6. Проверьте контейнеры и API

    docker compose ps
curl http://localhost:8000/health

    PowerShell вместо curl:

    Invoke-RestMethod http://localhost:8000/health

    Ожидаемо: docker compose ps показывает четыре строки в состоянии Up с пометкой (healthy); /health отвечает HTTP 200 и телом {"status":"ok"}. Healthcheck-и стартуют не сразу: start_period 10 секунд у postgres и api, 15 секунд у worker. Если статус starting, подождите до минуты и повторите.

  7. Примените миграции

    uv run alembic upgrade head

    Ожидаемо: семь строк Running upgrade …, последняя с номером 0007. Повторный запуск ничего не делает и завершается с кодом 0. 

    uv run alembic check

    Ожидаемо: No new upgrade operations detected.

    Миграции отдельным шагом

    API миграции при старте не применяет. Без этого шага страницы вернут ошибку обращения к несуществующим таблицам, хотя /health уже отвечает.

  8. Создайте пользователя, проект и токен

    Регистрации в интерфейсе нет: учётную запись создаёт scripts/seed_demo.py. 

    export DEMO_PASSWORD='<пароль не короче 8 символов>'
export DEMO_REPO_URL='https://github.com/arslan-ahmetjanov/patches-please-demo.git'
uv run python scripts/seed_demo.py

    PowerShell:

    $env:DEMO_PASSWORD = "<пароль не короче 8 символов>"
$env:DEMO_REPO_URL = "https://github.com/arslan-ahmetjanov/patches-please-demo.git"
uv run python scripts/seed_demo.py

    Ожидаемо: код возврата 0 и вывод вида

    пользователь создан: demo@example.com
проект создан: patches-please-demo (<uuid>)
токен создан: ci (<uuid>)

демо-стенд готов: пользователь demo@example.com, проект patches-please-demo (<uuid>)
токен проекта (показывается один раз): pp_…

    Токен печатается один раз: в базе хранится только SHA-256. Сохраните значение, оно нужно для прогона. Код возврата 1 означает ошибку параметров, подключения или описи. Повторный запуск с теми же параметрами не создаёт дублей.

Проверка

Стенд отвечает, если docker compose ps показывает четыре контейнера без перезапусков, а /health возвращает {"status":"ok"}. Дальше проверьте остальные адреса:

Что открывается после установки
Адрес Что там
http://localhost:8000/login Форма входа. Учётная запись создана на шаге 8.
http://localhost:8000/projects Список проектов пользователя после входа.
http://localhost:8000/docs Интерактивная схема REST API.

Логи обоих приложений, если что-то не отвечает:

docker compose logs -f --tail=100 api worker

Порядок разбора типовых сбоев и таблица «симптом, причина, что делать» лежат на странице «Неполадки».

Что дальше

  • Смените пароль базы и разберитесь с APP_ENV: «Настройка».
  • Запустите первый прогон и поставьте опись: «Первый прогон».
  • Подключите проверку к пайплайну: «CI».
Перед показом

Пароль PostgreSQL по умолчанию годится только для локального стенда: перед демонстрацией смените его в .env и в DATABASE_URL. Файл .env не коммитится.
