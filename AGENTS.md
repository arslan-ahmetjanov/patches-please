# AGENTS.md

Инструкции для агентов, работающих в этом репозитории.

## Проект

Security Gate — информационная система автоматизированного контроля безопасности разработки для CI/CD. Дипломный проект (ВКР, 09.03.03 «Прикладная информатика», УГНТУ).

Репозиторий: `arslan-ahmetjanov/security-gate`, приватный.

## Процесс: SDD

Спецификация — источник правды, код — её следствие.

1. Перед любой работой прочитай `specs/security-gate-mvp/spec.md`, `plan.md` и `tasks.md` целиком.
2. Любое изменение поведения начинается с правки спецификации, а не с кода. Изменение после выпуска — через delta-спеку.
3. Бери задачи по порядку из `tasks.md`. Задача без ID требования не выполняется.
4. Код и спецификация расходятся — остановись и спроси. Молча подгонять спеку под код запрещено.
5. Сделанная задача закрывается одним коммитом: код, тесты, при необходимости правка спеки.

## Структура

```
app/                     # api, worker, scanners, normalize, policy, reports, web
specs/security-gate-mvp/ # спека, план, задачи
contracts/               # OpenAPI и схемы
tests/                   # pytest, фикстуры SARIF
docs/                    # инструкции, замеры, лицензии
demo/                    # демо-репозиторий с внедрёнными уязвимостями
```

## Стек

Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 + Alembic, PostgreSQL 16, Redis + RQ, Jinja2 + HTMX, pytest, ruff, mypy. Всё через Docker Compose.

## Команды

- `uv sync` — зависимости
- `docker compose up -d` / `down` — стек
- `uv run alembic upgrade head` — миграции
- `uv run pytest -m "not integration"` — быстрые тесты
- `uv run pytest -m integration` — тесты с БД
- `uv run ruff check .` / `uv run ruff format .` — линт и формат
- `uv run mypy app` — типы

## Соглашения

- Интерфейс, документация и сообщения коммитов — на русском. Код, имена переменных и таблиц — на английском.
- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.
- Тест ссылается на ID требования в имени или комментарии, например `test_fr_005_blocks_on_new_critical`.
- Новый эндпоинт или поле в ответе — сначала правка `contracts/openapi.yaml`.
- Секреты и токены — только хешами, в логи и отчёты не попадают.
- Сканеры запускаются подпроцессом списком аргументов, без `shell=True`.

## Границы

**Всегда:** тесты перед коммитом, валидация входов на границе API, обратимая миграция, маскирование находок-секретов.

**Спросить:** изменение схемы БД после первого прогона, новая зависимость, правка CI-шаблонов, изменение формата отчёта, выход за скоуп текущей задачи.

**Никогда:** данные работодателя в репозиторий, отчёты и коммиты; секреты в открытом виде; `docker.sock` внутри worker; удаление падающего теста без разбора; правка чужих файлов ради «заодно».

## Готово, когда

- Тесты по требованию зелёные, линт и типы чистые.
- Проверка из задачи `tasks.md` выполнена и описана в отчёте.
- Спека и контракт соответствуют фактическому поведению.
- В отчёте отдельно перечислено, что осталось вне скоупа.
