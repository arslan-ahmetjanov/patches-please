## Что произошло

27.11.2026 на репозитории включили Dependabot alerts (`PUT
/repos/{owner}/{repo}/vulnerability-alerts`). GitHub сразу показал 11 алертов:
1 critical, 1 high, 9 moderate.

**Все 11 сидят в `demo/requirements.txt`, то есть в учебном манифесте демо-репозитория.**
По зависимостям приложения (`pyproject.toml`, `uv.lock`) открытых алертов нет.

Манифест уязвим намеренно: это объект проверки для T-032 и CON-003. Trivy читает
`requirements.txt` и находит там CVE, а нужен этот файл ровно для того, чтобы
демонстрация показывала находки класса «уязвимые зависимости». Зависимости из
него не устанавливаются, код библиотек не запускается, приложение не
разворачивается.

Содержимое `demo/requirements.txt`:

```text
requests==2.20.0
PyYAML==5.3.1
Jinja2==2.10
```

## Развилка, которую надо решить

**Вариант A, закрыть алерты осознанно (рекомендуется).** Каждый алерт
закрывается как `tolerable_risk` с комментарием: файл учебный, зависимости не
устанавливаются, версии менять нельзя, иначе сломается демонстрация Trivy.
После этого открытых алертов ноль, а причина видна в комментарии и в
документации. Так репозиторий перед защитой не выглядит заброшенным.

**Вариант B, оставить открытыми и объяснить.** Алерты сами по себе честно
показывают, что демо-манифест уязвим. Тогда задача закрывается не закрытием
алертов, а разделом в `docs/demo.md` и фразой на защите: «алерты относятся к
учебному манифесту, а не к коду продукта». Минус: посторонний читатель видит
11 открытых алертов и делает вывод раньше, чем читает объяснение.

**Вариант C, обновить версии в `demo/requirements.txt`.** Не делать. Это ломает
T-032 и CON-003: демонстрация должна находить уязвимые зависимости, а число
находок Trivy записано в `docs/demo.md` и в отчётах. Кроме того, придётся
переопубликовать демо-репозиторий.

`ignore` в `.github/dependabot.yml` по именам пакетов тоже не годится: `jinja2`
есть и в зависимостях приложения (`pyproject.toml`, `jinja2>=3.1.6`), поэтому
глобальный ignore по имени скрыл бы настоящие алерты продукта.

## Что сделать по варианту A

1. Подтвердить, что все открытые алерты относятся к `demo/requirements.txt`:
   `gh api "repos/arslan-ahmetjanov/patches-please/dependabot/alerts?state=open&per_page=100" --jq '.[].dependency.manifest_path' | sort -u`.
   Если появился алерт по другому манифесту, его разбирать отдельно и не
   закрывать пачкой.
2. Закрыть каждый алерт: `PATCH
   /repos/arslan-ahmetjanov/patches-please/dependabot/alerts/{number}` с телом
   `{"state": "dismissed", "dismissed_reason": "tolerable_risk",
   "dismissed_comment": "Учебный манифест demo/requirements.txt для
   демонстрации Trivy (T-032, CON-003). Зависимости не устанавливаются, код не
   запускается, версии менять нельзя."}`.
   Комментарий до 280 символов, кириллица допустима, но передавать его надо
   файлом через `--input`, а не флагом `-f`: `cmd.exe` съедает кавычки.
3. Добавить в `docs/demo.md` короткий раздел «Dependabot и demo/requirements.txt»:
   почему манифест уязвим, почему алерты закрыты как `tolerable_risk`, что
   обновлять версии в нём нельзя, и как это объяснять на защите.
4. Дописать строку в `docs/next-session-prompt.md`: алерты разобраны, решение и
   дата.
5. Проверить: открытых алертов ноль, закрытых 11, у каждого есть комментарий.
   Собрать доказательство в отчёт.

## Границы

- Не менять `demo/requirements.txt`, `demo/app.py`, `contracts/`, схему БД,
  миграции, `patches_please/cli.py`, `.github/workflows/`, `ci/`.
- Не добавлять и не обновлять зависимости приложения: по ним алертов нет, а
  `uv.lock` меняется только через `uv add` или `uv lock`.
- Одна задача, один коммит. Сообщения коммитов на русском, Conventional
  Commits. Push только по просьбе, если не сказано иное.
- Стиль текстов: без длинных тире, канцелярита и отглагольных существительных
  там, где хватает глагола. Порядок зафиксирован в `docs/next-session-prompt.md`.

## Особенности этой машины

- `cmd.exe` вырезает кавычки и `$`: сообщения коммитов писать в файл и
  использовать `git commit -F`, JSON для `gh api` передавать через `--input`.
- PowerShell 5.1 читает `.ps1` в системной кодировке: служебные скрипты писать
  ASCII, русский вывод направлять в файл.
- Docker Desktop засыпает при простое: перед тестами `docker desktop start` и
  дождаться `/health` на `http://localhost:8081` (порт из `.env`, в контейнере
  8000). После старта порты появляются не сразу.
- `gh run watch ... & echo %ERRORLEVEL%` в `cmd.exe` печатает старое значение,
  результат смотреть отдельной командой.
